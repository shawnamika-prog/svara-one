# Sound Studio UI Audit — S9-1

**Baseline:** `466d40d26e97b0313962604980d2ac48cabc58d3`
**Scope:** Audit only. No existing Sound/Voice behavior changed by S9-1.

## 1. Current Sound UI location

The Sound workspace is currently generated by `public/js/studio-landing.js`, rather than being a standalone Sound HTML page. The script dynamically injects Sound-specific CSS and creates the Sound workspace when the Studio navigation opens Sound.

`public/studio.html` contains the shared Studio shell, navigation, Voice workspace and Library markup. The Sound workspace is not present as static markup there.

## 2. Existing Sound presentation

The current mockup already contains a two-column Sound workspace with:

- Sound creation panel
- Prompt textarea
- Sound type choices
- Mood choices
- Creative controls
- Advanced controls
- Generate button
- Output panel
- Empty-state waveform visual
- Result waveform visual
- Play control
- Output actions
- Variations area
- Mobile responsive rules

The visual implementation is currently mockup-oriented and is embedded in `studio-landing.js`.

## 3. Current Sound visual controls identified

Existing Sound UI concepts include:

- Prompt
- Sound types: music, soundtrack, SFX, ambience, jingle and loop
- Mood selection
- Additional creative controls
- Advanced controls
- Generate
- Output/playback presentation
- Actions and variations

These controls are candidates for wiring to the SvaraONE Sound state model. They must not be assumed to map one-to-one to a provider's API.

## 4. Existing backend boundary to preserve

S9 UI work must use the existing Sound API and normalized capability layer. The provider contract explicitly keeps provider-specific authentication, request mapping, capability discovery and response parsing inside provider adapters; the Sound API owns authentication, validation, credits and generation persistence.

Therefore the UI must not call Sonilo directly or embed Sonilo-specific request logic.

## 5. Existing capability path to reuse

The current backend already exposes normalized Sound provider capabilities. S9 should consume those capabilities and use them to determine which controls and constraints are executable.

Target boundary:

```text
Sound Studio UI
      ↓
SvaraONE Sound API / capability endpoint
      ↓
Normalized Sound capability model
      ↓
Sound Studio state
```

## 6. Files identified for S9 work

Primary files:

- `public/studio.html` — shared Studio shell and navigation; protect Voice markup.
- `public/js/studio-landing.js` — current dynamically generated Sound workspace and its navigation/view behavior; primary S9 integration point.
- `public/css/studio-v2.css` — shared Studio styling; avoid unnecessary changes to Voice styling.
- Existing Sound backend files remain outside S9 UI scope except where the already-defined API contract is consumed.

## 7. Files/areas to protect

Do not refactor during S9:

- Voice provider system
- Voice generation route
- Existing Voice workspace behavior
- Voice audio tools
- Voice registry
- Voice R2 namespace
- Sound provider adapters
- Sound D1 schema
- Sound R2 persistence
- Sound credit implementation
- SvaraFlow Voice intelligence

## 8. Important boundary for later phases

The existing mockup includes playback, waveform, actions and variations visually. S9 will establish the output state and handoff, but full functional audio playback remains S10.

SvaraFlow Sound intelligence remains S12.
Composition remains S14/S15.
Export remains S16.
Shared Library remains S17.

## 9. S9-1 conclusion

The existing Sound UI is a dynamically generated mockup inside `studio-landing.js`. It already provides substantial visual structure that can be progressively converted into the real Sound Studio without rebuilding the Studio shell.

The safest S9 path is therefore:

1. Keep the current visual structure.
2. Extract/organize Sound state and behavior without changing Voice behavior.
3. Connect normalized capabilities.
4. Replace mock controls with real state-backed controls.
5. Wire generation through the existing Sound API.
6. Leave playback implementation to S10.

**S9-1 audit complete.**
